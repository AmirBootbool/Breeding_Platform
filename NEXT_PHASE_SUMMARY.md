# Next Phase Summary

Date: 2026-07-31

## Current State

Phases 1–10 are fully complete and verified.

The platform provides:

- Hardened Django configuration, token/session authentication, role-based
  access, structured errors, throttling, and production logging.
- CRUD APIs for programs, locations, seasons, profiles, germplasm, crosses,
  trials, plots, observation variables, and observations.
- Filtering, searching, ordering, RCBD/alpha-lattice/augmented plot generation,
  trial summaries, and CSV/Field Book exchange.
- **Alpha-lattice and Augmented Designs**: Extended layout generators, plot
  model fields (incomplete_block, is_check), and layout generator modals with
  divisibility validation and check designation.
- Bulk CSV germplasm import from both CLI and browser UI.
- Bulk observation entry via a spreadsheet grid with whole-batch rollback.
- Audit trail (`created_by`/`updated_by`) on core models, surfaced in the Setup page.
- Streaming HTTP export endpoints: `GET /api/trials/{id}/export_csv/` and
  `GET /api/trials/{id}/export_fieldbook/`.
- Read-only BrAPI v2 compatibility endpoints.
- OpenAPI schema, Swagger UI, and ReDoc generated by drf-spectacular.
- Gunicorn, WhiteNoise, health checks, Redis/Sentry integration, and CI validation.
- A verified baseline of **95 passing tests** and 1 optional Sentry test
  skipped when the production dependency is absent.

### Frontend (complete and verified)

A Vite + React + TypeScript SPA has been built at `frontend/`. It
provides a fully self-contained experience for breeders:

- **Login** — token auth form with Zustand persistence.
- **Dashboard** — stat cards, program grid, recent observations.
- **Germplasm Browser** — search, filter, pedigree detail panel, full
  Create/Edit/Delete modals, and CSV bulk import modal.
- **Trial Manager** — trial list, plot grid (showing incomplete blocks and check plots styled appropriately), layout generator modal, multi-trait summary chart, and full Create/Edit/Delete modals.
- **Observation Entry** — trial → plot → traits form with inline validation,
  plus a spreadsheet grid mode for bulk data entry.
- **Data Export** — authenticated CSV and Field Book downloads.
- **Setup** — Role-gated admin page to manage Programs, Locations, Seasons,
  and Observation Variables with full CRUD and audit trail columns.

The frontend proxies `/api/` to Django via the Vite dev server. A `frontend`
service is added to `docker-compose.yml`.

## Next Target: Phase 11 — BrAPI v2 Write Support

Add write operations (POST/PUT) for observations, observation units (plots), and germplasm to allow BreedBase, Field Book, and other external clients to push data directly to the breeding platform.

Key deliverables:
1. `BrapiObservationWriteSerializer` (POST/PUT observations).
2. `BrapiObservationUnitWriteSerializer` (PUT plots to update status only).
3. `BrapiGermplasmWriteSerializer` (POST germplasm accessions).
4. `set_typed_value(raw_value)` helper on the `Observation` model to parse values uniformly.
5. Integration with the existing `RoleBasedPermission` layer.

See `IMPLEMENTATION_ROADMAP.md` Phase 11 for full details.

## Engineering Conventions

- Shared domain state belongs in `apps.core`; pedigree concerns in
  `apps.germplasm`; trial concerns in `apps.trials`; BrAPI translations in
  `apps.brapi`.
- Models own invariants, serializers own API shape, and services own
  cross-model workflows.
- Multi-row writes use transactions; related API querysets use
  `select_related`/`prefetch_related`.
- Bulk exchange belongs in management commands or streaming viewset actions.
- Settings use `python-decouple` and environment values.
- Model/service tests live under `apps/*/tests`; API and integration tests live
  under `backend/tests`.
- Frontend components live in `frontend/src/components/`, pages in
  `frontend/src/pages/`, the API client in `frontend/src/api/client.ts`, and
  auth state in `frontend/src/store/authStore.ts`.
