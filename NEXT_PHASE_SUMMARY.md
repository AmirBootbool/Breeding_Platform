# Next Phase Summary

Date: 2026-08-12

## Current State

Phases 1–13 are fully complete, verified, and committed.

The platform provides:

- Hardened Django configuration, token/session authentication, role-based access, structured errors, throttling, and production logging.
- CRUD APIs for programs, locations, seasons, profiles, germplasm, crosses, trials, plots, observation variables, and observations.
- Filtering, searching, ordering, RCBD/alpha-lattice/augmented plot generation, trial summaries, and CSV/Field Book exchange.
- **Alpha-lattice and Augmented Designs**: Extended layout generators, plot model fields (incomplete_block, is_check), and layout generator modals with divisibility validation and check designation.
- Bulk CSV germplasm import from both CLI and browser UI.
- Bulk observation entry via a spreadsheet grid with whole-batch rollback.
- Audit trail (`created_by`/`updated_by`) on core models, surfaced in the Setup page.
- Streaming HTTP export endpoints: `GET /api/trials/{id}/export_csv/` and `GET /api/trials/{id}/export_fieldbook/`.
- **BrAPI v2 write compatibility** for observations (POST/PUT), observation units (PUT status), and germplasm (POST).
- OpenAPI schema, Swagger UI, and ReDoc generated by drf-spectacular.
- Gunicorn, WhiteNoise, health checks, Redis/Sentry integration, Prometheus metrics logging (/api/metrics/), and Recent Changes audit logs.
- Phenotypic multi-environment broad-sense heritability estimation ($H^2$) using mixed linear models and cross-environment genotype ranking.
- A verified baseline of **113 passing tests** and 1 optional Sentry test skipped when the production dependency is absent.

### Frontend (complete and verified)

A Vite + React + TypeScript SPA has been built at `frontend/`. It provides a fully self-contained experience for breeders:

- **Login** — token auth form with Zustand persistence.
- **Dashboard** — stat cards, program grid, recent observations.
- **Germplasm Browser** — search, filter, pedigree detail panel, full Create/Edit/Delete modals, and CSV bulk import modal.
- **Trial Manager** — trial list, plot grid (showing incomplete blocks and check plots styled appropriately), layout generator modal, multi-trait summary chart, and full Create/Edit/Delete modals.
- **Observation Entry** — trial → plot → traits form with inline validation, plus a spreadsheet grid mode for bulk data entry.
- **Data Export** — authenticated CSV and Field Book downloads.
- **Setup** — Role-gated admin page to manage Programs, Locations, Seasons, and Observation Variables with full CRUD, and the audit trail "Recent Changes" tab.
- **Multi-Environment Analysis** — page displaying analysis set builder, heritability bands card, adjusted ranking data table, and Recharts grouped bar charts showing GxE performance.

The frontend proxies `/api/` to Django via the Vite dev server. A `frontend` service is added to `docker-compose.yml`.

## Engineering Conventions

- Shared domain state belongs in `apps.core`; pedigree concerns in
  `apps.germplasm`; trial concerns in `apps.trials`; BrAPI translations in
  `apps.brapi`.
- Models own invariants, serializers own API shape, and services own
  cross-model workflows.
- Multi-row writes use transactions; related API querysets use
  `select_related`/`prefetch_related`.
- Bulk exchange belongs in management commands or streaming viewset actions.
- Settings use `python-decouple` and environment values.
- Model/service tests live under `apps/*/tests`; API and integration tests live
  under `backend/tests`.
- Frontend components live in `frontend/src/components/`, pages in
  `frontend/src/pages/`, the API client in `frontend/src/api/client.ts`, and
  auth state in `frontend/src/store/authStore.ts`.

## Verification

After a backend change:

```powershell
cd backend
.\.venv\Scripts\python -m pytest -q
```

For schema-affecting changes:

```powershell
.\.venv\Scripts\python manage.py spectacular --file openapi.yaml --validate
```

For frontend type checking:

```powershell
cd frontend
npx tsc --noEmit
```
