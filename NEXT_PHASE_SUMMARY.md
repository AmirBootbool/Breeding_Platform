# Next Phase Summary

Date: 2026-09-12

## Current State

Phases 1–21 are fully complete, verified, and committed. Phase 21
(multi-tenant program scoping & crash hardening) closed the last known gap
between RBAC (which role can act) and per-program data isolation (which
program's rows a role can act on) — see
[IMPLEMENTATION_ROADMAP.md](IMPLEMENTATION_ROADMAP.md) Phase 21 for detail.

This document tracks phase-level engineering status. For day-to-day
feature documentation aimed at breeders, technicians, and genomics staff,
see [docs/WIKI.md](docs/WIKI.md) and its 11 chapters — that manual is the
up-to-date, feature-complete reference this file used to duplicate.

The platform now provides, across five backend domain apps
(`apps.core`, `apps.germplasm`, `apps.trials`, `apps.genomics`, `apps.brapi`):

- Hardened Django configuration, token/session authentication, role-based
  access, structured errors, throttling, and production logging.
- CRUD APIs for programs, locations, seasons, profiles, germplasm, crossing
  blocks, crosses, seed lots/transactions, trials, plots, observation
  variables/panels, observations, analysis sets, genotype datasets, genomic
  predictions, and diagnostic markers/scores.
- Filtering, searching, ordering, and six experimental design generators
  (RCBD, alpha-lattice, augmented, p-Rep, Latin Square, unreplicated), plus
  an interactive Map Wizard and Plot Editor for manual layout correction.
- **Crossing Blocks & diallel matrices**: planned → pollinated →
  harvested/failed lifecycle with automatic F1 germplasm + seed-lot
  creation on harvest.
- **Seed Inventory**: gram-level lot tracking, a transaction ledger, lot
  splitting, low-stock alerts, and barcode/QR label sheets.
- **Interactive pedigree tree visualizer** with recursive ancestry tracing.
- **Spatial field heatmaps** coloring the plot grid by live trait values.
- **Offline-first PWA field scoring**: installable app, trial caching to
  IndexedDB, offline observation queueing, and a Sync Center for batch
  upload with per-record validation feedback.
- **Genomic Selection & MAS** (`apps.genomics`): VCF/HapMap/matrix genotype
  ingestion with QC/imputation, a VanRaden G-matrix, a Henderson GBLUP
  solver producing GEBVs with cross-validation accuracy and reliability,
  and a diagnostic-marker library with MAS trait-stacking analysis.
- Bulk CSV germplasm import, bulk observation entry via spreadsheet grid,
  `created_by`/`updated_by` audit trail surfaced in the Setup page, and an
  automated 7-generation (F0→F7) breeding-cycle simulator for demo data.
- Streaming CSV/Field Book export endpoints and BrAPI v2 compatibility
  (read + write for observations, observation units, and germplasm).
- OpenAPI schema, Swagger UI, and ReDoc generated by drf-spectacular.
- Gunicorn, WhiteNoise, health checks, Redis/Sentry integration, Prometheus
  metrics, production Docker Compose behind an Nginx reverse proxy, and a
  Playwright end-to-end browser test suite.
- Phenotypic multi-environment broad-sense heritability estimation ($H^2$)
  and cross-environment genotype ranking via mixed linear models.
- Multi-tenant program scoping (`ProgramScopedQuerySetMixin`) enforced
  across every domain viewset, including BrAPI, so a request can only see
  or write its own program's rows; malformed query params/payloads return
  clean `400`s instead of 500ing (Phase 21).
- **261 tests** (260 passed, 1 skipped), verified via
  `pytest -q` after Phase 21 landed. `openapi.yaml` regenerates with 0
  errors.

### Frontend (complete and verified)

A Vite + React + TypeScript SPA at `frontend/` provides a fully
self-contained breeder experience. Pages (`frontend/src/pages/`):
`Login`, `Dashboard`, `GermplasmBrowser`, `CrossingBlock`, `SeedInventory`,
`TrialManager`, `ObservationEntry`, `MultiEnvironmentAnalysis`,
`Genomics`, `Traits`, `Setup`, `AuditTrail`, `DataExport` — each backed by
full CRUD, role-gating, and (where relevant) offline support via
`services/offlineStorage.ts` and `services/syncManager.ts`.

The frontend proxies `/api/` to Django via the Vite dev server. Both a dev
`docker-compose.yml` and a production `docker-compose.prod.yml` (behind
Nginx) are provided.

## Engineering Conventions

- Shared domain state belongs in `apps.core`; pedigree, crossing, and seed
  inventory in `apps.germplasm`; trial and phenotyping concerns in
  `apps.trials`; genomic prediction and MAS in `apps.genomics`; BrAPI
  translations in `apps.brapi`.
- Models own invariants, serializers own API shape, and services own
  cross-model workflows.
- Program-scoped viewsets inherit `apps.core.mixins.ProgramScopedQuerySetMixin`
  (Phase 21) so a request only ever sees or writes its own program's rows;
  platform staff/superusers are the only exception.
- Multi-row writes use transactions; related API querysets use
  `select_related`/`prefetch_related`.
- Bulk exchange belongs in management commands or streaming viewset actions.
- Settings use `python-decouple` and environment values.
- Model/service tests live under `apps/*/tests`; API and integration tests live
  under `backend/tests`.
- Frontend components live in `frontend/src/components/`, pages in
  `frontend/src/pages/`, the API client in `frontend/src/api/client.ts`, and
  auth state in `frontend/src/store/authStore.ts`.

```powershell
cd backend
.\.venv\Scripts\python -m pytest -q
```

For schema-affecting changes:

```powershell
.\.venv\Scripts\python manage.py spectacular --file openapi.yaml --validate
```

For frontend type checking:

```powershell
cd frontend
npx tsc --noEmit
```
